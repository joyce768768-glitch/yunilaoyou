# 与你老友 · 体验指标体系 L0 手册

> 版本 v1.1 · 2026-10-17 · 用途：产品迭代仪表盘 + AX/AI 方法论叙事（双轨）
> 一句话主线：**「五度」测 AI 灵魂，「五性」测 GUI 躯壳；双结果 ERD × BOND 确认灵魂与躯壳咬合得让用户愿意留下。**

---

## 0. 体系总览

```
L1  结果层（两个价值假设）
    ERD  · 有效圆桌深度 —— 圆桌值不值得来（话语权回归）
    BOND · 单聊关系回流 —— AI 老友是不是真的老友（关系回流）
      │ 由诊断层解释
L2  诊断层：AI 体验「五度」    GUI 体验「五性」
    像 · 保真度               成 · 任务成功
    真 · 真实度               效 · 效率
    萌 · 温度                 敏 · 性能感知
    合 · 协同度               一 · 一致性
    快 · 速度                 韧 · 可恢复性
      └───────┬───────┘
L3  交互耦合点：LLM 等待 × 生成失败 × 积分墙 × 首插话
      │
L4  数据源地图：已有 8 类 + 需新增 4 类（§7）
```

设计原则：
1. AI 体验是一等公民，不是 GUI 指标的附录——传统 HEART 测不出「德鲁克像不像德鲁克」
2. 每个指标必须绑定真实数据源（§7），可采集才可管理
3. **分层即分工：结果层只放行为结果（ERD/BOND），诊断层只放可判卷/可埋点的质量属性**——五度五性全部能对单条回应或单次交互打分，杜绝 driver 与 outcome 混层
4. AI 与 GUI 在耦合点交汇（§6），双视角共用同一埋点

## 1. 结果层定义卡：ERD × BOND

### 1.1 北极星：有效圆桌深度 ERD

| 项 | 定义 |
|---|---|
| ID | ERD-01 |
| 名称 | 有效圆桌深度（Effective Roundtable Depth） |
| 公式 | `ERD = Σ(有效轮次 × 质量系数) ÷ 周活跃用户` |
| 有效轮次 | 用户插话 → AI 回应成功 → **回归判定通过**（见下） |
| 回归判定 v1（零埋点，现版） | AI 回应完成后 **10 分钟内同桌再插话**（纯 rec.cache 时序可判） |
| 回归判定 v2（N2 埋点后升级） | 10 分钟内命中任一信号：① 同桌再插话 ② 前台读回应 ≥3s ③ 桌内任意交互（滚动/点赞/复制）；历史回溯数据须标注口径版本 |
| 判定哲学 | 参与的金标准是**话语权回归**，不是挂机时长——「用户愿意用话语回应的轮次，才算有效的轮次」；切桌/切后台不构成退出，只是不加分 |
| 质量系数 | 该桌实录周抽样的 judge 四维均分（像/真/合 + 萌）÷ 100，无抽样时取 1.0 |
| 数据源 | yln_rounds 实录（rec.cache 轮次序列）+ N2 埋点（v2 信号②③）+ L2 抽样 judge 分 |
| 频率 | 周频（周一出上周值） |
| 为什么是它 | 同时惩罚「只围观不插话」（量不足）与「插话了但 AI 答得水」（质不足）；三个变量全部可从现有数据计算 |
| 基线 | L1 看板上线后采集 2 周得出 |
| 目标 | 基线确定后定（建议 +20%/季） |

**口径红线**：
- 演示桌（剧本数据）一律不计入——不是真实用户对话
- 免费桌与付费桌同权重计（ERD 是体验指标，商业化另有漏斗）
- 单聊不计入 ERD（属关系留存叙事，见 W-03），避免口径互污；**单聊回归也不算回归信号**（防单聊刷量）
- 切桌 / APP 切后台不构成退出信号；窗口内回来插话照样有效
- AI 生成期间的用户退出由 R-03（等待中断率）负责，不污染 ERD 判定
- 判定窗口从「AI 回应完成」起算（不从插话起算），10 分钟窗口对慢思考与深夜节奏基本免疫

**v1 → v2 升级路径**：v1 上线即全量可算；N2 埋点上线后切 v2 三信号，切换当周双口径并行输出一周做对齐校验，之后 v1 退役。

### 1.2 次级结果卡：单聊关系回流 BOND

| 项 | 定义 |
|---|---|
| ID | BOND-01（原 W-03，自萌温度柱升格） |
| 名称 | 单聊关系回流（Bond Return） |
| 定义 | 与某老友单聊后 7 日内再次与其对话（单聊或同桌）的用户占比 |
| 子口径 BOND-01b | 圆桌迁移率：回流场景为**圆桌**的占比——单聊养熟的关系被带进圆桌，是「单聊是圆桌的关系入口」的证据，也是最强关系信号 |
| 数据源 | yln_rounds（solo 桌时间序列，现成可算） |
| 频率 | 周频 |
| 为什么独立成结果 | 五度全部是回应级可判卷质量，回流是用户跨时间行为——留在 W 柱会归因混淆（温度≠回流唯一原因）且与 ERD 重复计量 |
| 基线 | L1 看板上线后采集 2 周得出 |

> 与 ERD 的分工：ERD 回答「圆桌值不值得来」，BOND 回答「AI 老友是不是真的老友」——分别锚定产品的两个价值假设。ERD 红线中「单聊回归不算回归信号」与本卡互为呼应：单聊回归有自己的家。

## 2. AI 体验「五度」

### 2.1 像 · 保真度 Fidelity——回答像不像角色本人

**F-01 黑盒评测放行分（P0，现成）**
- 定义：新建老友蒸馏完成后，黑盒评测（probeJudge）判卷分
- 口径：score ≥ 70 放行；< 70 进复核队列
- 数据源：yln_nuwa_traces（/api/traces，女娲页已有观测）
- 频率：每新建/重蒸必测
- 注意：分数只做放行门槛，**不得作为长期 KPI 优化目标**（§9 红线 1）

**F-02 存量人设保真抽检分（P0，L2 流水线后生效）**
- 定义：已发布老友在真实对话中「像本人」的程度衰减监测
- 口径：每周每老友随机抽 3 条实录回应，judge 按「语言指纹 / 心智模型使用 / 禁忌回避」三维打 0-100
- 数据源：实录抽样器（N1）+ probeJudge 扩展判卷

**P1 扩展**

| ID | 指标 | 口径 | 数据源 |
|---|---|---|---|
| F-03 | 人设违例率 | 踩禁忌/反模式/越过认知边界的回应占比 | L2 judge issues 分类 |
| F-04 | 语录贴贴率 | 语录变体角色「只贴语录不推理」的占比（反向） | L2 judge |

### 2.2 真 · 真实度 Veracity——编不编造

**V-01 事实题探针准确率（P0）**
- 定义：预置事实题库（书籍/人物/事件/数据类），定期探针检测回答是否给出真实内容
- 口径：judge 判「实体真实 + 关键概念正确 + 无编造」的比例
- 数据源：探针题库（种子：《原子习惯》→ 克利尔 / 1%→37 倍复利，任务 I 用例直接入库）+ N1 探针运行
- 频率：每周 1 轮，每老友 2 题

**V-02 实体幻觉率（P0，与 V-01 同轮采集）**
- 定义：回答中书名/人名/数字类实体的编造比例（反向指标）
- 口径：judge 标注 issues 中 hallucination 类计数 ÷ 抽检回应数

**P1 扩展**

| ID | 指标 | 口径 | 备注 |
|---|---|---|---|
| V-03 | 诚实触发率 | 「不确定/没把握」出现率 | **区间指标**：过高=过度防御，过低=过度自信；健康区间待基线 |
| V-04 | 越界作答率 | 超出老友诚实边界声明仍作答的占比 | 与 F-03 互查 |

### 2.3 萌 · 温度 Warmth——呆萌但锋利，有情绪价值

**W-01 品牌调性符合度（P0，L2 后生效）**
- 定义：judge 按「呆萌底色 + 思想锋利 + 有情绪有笑点」打 1-5 分
- 口径：抽检回应调性均分
- 数据源：N1 抽样 + judge

**W-02 气泡正向信号率（P0，埋点 N3 后生效）**
- 定义：AI 气泡被 复制 / 👍 / 触发追问（同老友 3 轮内用户再发言）的比例
- 口径：正向信号气泡数 ÷ AI 气泡总数
- 数据源：气泡级行为埋点（N3）

> 原 W-03「单聊 7 日回流率」已升格为结果层 BOND-01（§1.2）——柱内只保留回应级可判卷指标。

**P1 扩展**

| ID | 指标 | 口径 | 数据源 |
|---|---|---|---|
| W-04 | 长度合规率 | 回应 ≤120 字条款命中占比（纯规则可算） | 实录 |

### 2.4 合 · 协同度 Synergy——圆桌多角色独有

**S-01 观点碰撞率（P0）**
- 定义：一轮内出现 @引用或观点对冲的轮次占比
- 口径：含碰撞轮次数 ÷ 有 ≥2 AI 回应的轮次数（文本模式初筛 + judge 复核）
- 数据源：实录 rec.cache

**S-02 同轮观点重复度（P0，L2 后生效，反向指标）**
- 定义：同轮两个角色观点实质雷同（换皮不换观点）的轮次占比
- 口径：judge 判定雷同轮数 ÷ 抽检轮数

**P1 扩展**

| ID | 指标 | 口径 | 备注 |
|---|---|---|---|
| S-03 | 纪要有效率 | chatSummary 三行纪要被判「准确概括本桌」的比例 | L2 |
| S-04 | 接话自然度 | 被判「顺着上条自然接话而非自说自话」的比例 | L2 |

### 2.5 快 · 速度 Responsiveness——快不快、稳不稳

**R-01 端到端响应时长 P50/P95（P0，埋点 N4 后生效）**
- 定义：用户插话 → AI 回应完整返回的时长
- 口径：当前为非流式（stream:false），即全时长；流式化后升级为 TTFT（首字延迟）
- 数据源：llmChat 计时埋点（N4）

**R-02 生成失败率（P0）**
- 定义：AI 回应失败（超时/异常/空回复）占比
- 口径：失败次数 ÷ 总生成次数
- 数据源：前端 catch 埋点 + token logs 缺失交叉验证

**P1 扩展**

| ID | 指标 | 口径 | 数据源 |
|---|---|---|---|
| R-03 | 等待中断率 | 生成中用户退出/切桌比例 | N4（与 P-02 同埋点双视角，耦合点 ①） |
| R-04 | 演示桌续播时长 | demo_next 加载耗时 | /api/live 计时 |

## 3. GUI 体验「五性」

### 3.1 成 · 任务成功 Task Success

**T-01 开桌漏斗完成率（P0，埋点 N2 后生效）**
- 口径：广场/老友页 → 选老友 → 发题 → 收到首条 AI 回应 的逐级转化

**T-02 捏人漏斗完成率（P0）**
- 口径：入口 → 蒸馏完成 → 发布 → 首次使用
- 数据源：女娲 traces（蒸馏发起/完成事件已有）+ 埋点补首用

**T-03 付费漏斗完成率（P0，现成可算）**
- 口径：套餐页 → 支付发起 → 到账（订单态=成功）
- 数据源：yln_site_orders + yln_wallet ledger

### 3.2 效 · 效率 Efficiency

| ID | 指标（P1） | 口径 |
|---|---|---|
| E-01 | 首插话步数/时长 | 新用户进 APP → 第一次成功插话 |
| E-02 | 老友发现路径深度 | 列表 → 选中目标老友的操作数 |
| E-03 | 重访直达率 | 老用户 ≤3 步回到最近一桌 |

### 3.3 敏 · 性能感知 Perceived Performance

| ID | 指标 | 级别 | 口径 |
|---|---|---|---|
| P-01 | 首屏 LCP（手机壳视图） | P0 | 常规 Web Vitals 口径 |
| P-02 | LLM 等待设计有效性 | P1 | 等待中退出率（与 R-03 同埋点，GUI 视角，耦合点 ①） |
| P-03 | 视图切换耗时 | P1 | tab/页面切换到可交互 |

### 3.4 一 · 一致性 Consistency

**C-01 三端静态断言通过率（P0，现成）**
- 口径：tests/run-tests.js 全量 PASS（当前基线 234）；一致性回归已在 O 组自动化
- 频率：每次改动 CI 内跑

**P1 扩展**

| ID | 指标 | 口径 |
|---|---|---|
| C-02 | 三端文案一致率 | 积分/老友券/套餐名等同名概念三端口径一致（抽检清单） |
| C-03 | 设计 token 偏差数 | 色值/圆角/字重离册数（像素眼巡检清单） |

### 3.5 韧 · 可恢复性 Resilience

**Re-01 积分墙挽回率（P0）**
- 定义：会员墙/积分不足出现后，用户完成 付费 / 用券 / 充值 任一挽回动作的比例
- 数据源：钱包 ledger + 订单（现成可算）

| ID | 指标（P1） | 口径 | 备注 |
|---|---|---|---|
| Re-02 | 降级可用性 | 服务器停机时本地降级功能完成率 | 单测覆盖先例 A5/A8/I4/I6，本项目的特色场景 |
| Re-03 | 错误恢复覆盖率 | 错误态均有重试/出口（巡检清单通过率） | 与 R-02 交汇（耦合点 ②） |

## 6. 需新增的埋点/采集（4 项）

| 编号 | 名称 | 说明 | 服务指标 |
|---|---|---|---|
| N1 | 实录周抽样器 | 每周每活跃桌随机 3 轮 × 全角色回应 → judge 四维判卷 | F-02 / V-01/02 / W-01 / S-01/02 / ERD 质量系数 |

## 8. 基线与目标节奏

1. **现成基线**（立即可读）：C-01 = 234 PASS；F-01 = traces 历史均分
2. **L1 看板上线后**：跑 2 周得 ERD / R 类 / T-03 / Re-01 / W-03 基线
3. **L2 流水线上线后**：跑 4 周得五度抽检分基线
4. 目标值统一在基线确定后设置（建议核心指标季度 +20%，反向指标季度 -30%）
5. 区间指标（V-03）只设健康区间，不设单边目标

---

## 9. 反模式红线（虚荣指标防线）

1. **不得把 probeJudge 分数当长期 KPI 优化**——会诱导人设模板讨好判卷官，分数失去意义；judge 分只做门槛与观测
2. **诚实触发率（V-03）是区间指标**——不追求单边最大化
3. **ERD 不奖励刷轮次**——质量系数加权 + 60s 退出判定 + 排除演示桌
4. **不为看板新增侵入式满意度弹窗**——主观信号只取行为信号（复制/👍/追问/回流）
5. **演示桌剧本数据不得混入任何用户侧指标**——仅用于性能类（R-04）
